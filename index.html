table name names the three database tables the SQL script fills: iw_par_<name>_param, iw_par_<name>_groups, iw_set_<name>. Lowercase letters/digits, e.g. kjol. plant number only appears in the SQL file name. The badge after each name is the default. Every checkbox also carries the same one-line summary as a hover tooltip.

Addressing

  • subtract_oneon — on when the device documentation counts registers from 1 (most do, incl. 4xxxx-style lists: 40101 → addr 101 → polled as 100). Off when the doc gives zero-based protocol addresses. Enter addresses exactly as documented — this switch handles the offset for every point at once. Validation fails if any address would go below 0.

Script shape

  • truncateon — emit TRUNCATE TABLE before the inserts (normal for a re-import). create_tablesoff — emit CREATE TABLE IF NOT EXISTS, needed the first time a plant gets this table.
  • Both are ignored by the modern SQL format, which is the default. Modern always writes CREATE TABLE IF NOT EXISTS and uses REPLACE INTO instead of truncate-then-insert, so neither checkbox changes its output. They only take effect with sql_format: legacy.

Alias text

  • use_system_noon · use_tagon · use_extraon — which per-point fields join into the alias. Order is fixed: system_no-tag-text-(extra) → 360.001-RT401-Romtemperatur-(1=Drift). A field that is empty on the point contributes nothing either way; the point's text is always included.
  • proper_case_stateson — Proper-case the words of a state text (drift på → Drift På), matching Excel's WorksheetFunction.Proper. Applies to both the JSON and the plain form. Turn off to keep Norwegian casing exactly as typed.

State texts

  • statetext_only_rwoff — emit the state-text JSON only for writable points (rw/vrw); read-only points keep their state list in the project but ship an empty format_extra.
  • statetext_in_aliasoff — also write the flattened state list into the point's extra, so it shows in the alias (…-(0=Av, 1=På)). Divergence: with this off Excel cleared the extra text of matched rows — here your extra is left untouched (docs/07 §7.3).

Points and groups

  • force_activeon — every point gets active=1 regardless of its own active field. Rows whose text is Reserve. stay inactive. Divergence: in Excel force_active overrode the Reserve rule; here Reserve wins, so a spare row stays inactive (docs/08 item 11).
  • include_minmaxoff — carry the point's range min/range max into the param record. Off leaves both columns blank even when the point has values, which is what the fleet does; the scaling table already supplies the raw/eng limits.
  • auto_groupsoff — fill an empty group cell from the datatype's default group, so points only need a group where you want to override it.
  • alarms_to_almoff — move every point with an alarm letter (A/B/C/N) into the alm group. Only runs when auto_groups is on — ticking this alone changes nothing.

Motherwords

A bit-addressed point needs its whole word polled once. Any row reading that address without a bit satisfies it — the literal text "Motherword" is not required.

  • auto_motherwordson — synthesize the missing word row for you, read-only, in the same group as the bit that needed it. Leave on unless you add motherword rows yourself.
  • require_motherwordsoff — promote a missing motherword from a soft warning to a hard error that blocks generation. Off, you get a warning naming the addresses and the script still generates.
  • exclude_motherwords_from_groupson — keep synthesized motherwords out of the display groups, so the operator sees the named bits rather than the raw word. Turn off only if the word itself should appear in the menu.

Groups

help
Groups decide how points are grouped in the IWMAC display. Left field = the short key you type in a point's group column (aio), right field = the name shown to the operator (Analoge inn/ut).
  • Every group used by a point must exist here — validation stops otherwise.
  • The five defaults (aio dio alm misc sch) are what nearly every existing plant list uses — one click adds them.
  • Display order in IWMAC = row order here.
  • The group key also becomes the first part of the point's element_id (aio_0_3_100), so pick keys before generating, not after.
  • A point with no grp ticked keeps its param/set rows but is left out of the group display (used for motherwords and helper registers).

State texts

help
A state list translates a register's numeric values into words in IWMAC — instead of the operator seeing 2, they see Avriming. Typical use: operating-mode and status registers whose documentation says something like "0 = Off, 1 = Run, 2 = Defrost".
  • Make one list per distinct enumeration in the device documentation, and give it a free-choice id number (1, 2, 3 …).
  • One state per line, written number=word:
    0=Av
    1=Drift
    2=Avriming
  • Keep the vendor's numbers exactly; translate only the words (Norwegian). Numbers must be 0 or higher — an enum with negative values cannot be a state list; leave that point without one.
  • Attach a list to a point by typing its id in the point's state column. Several points can share one list — define the enumeration once.
  • On generate, the list becomes the IWMAC state JSON in the point's format_extra field. The options statetext_only_rw (JSON only on writable points) and statetext_in_alias (plain text appended to the alias) fine-tune the behaviour.
  • A point with a state list usually needs no unit, scale or decimals.

Points

help
One row per Modbus point. Minimum per row: group, datatype, addr, text. Hover any column header for its meaning. Columns are described below in the order they appear.

Identity — group, datatype, addr, bit

  • group — must exist in the Groups card, or validation stops. It also builds the point's key: element_id = <group>_<driver_id> (aio_0_3_100) unless the project file overrides it.
  • datatype — the single most consequential column: it supplies the read and write function codes, raw type, byte/word swap, application class and parameter type. The "common" group covers nearly everything: A_Hold_I16_N analog holding register · A_Input_I16_N analog input register · I_Hold_U16_N plain integer/counter · Digital_X_N discrete input · Coil_X_N coil · Bit_Hold/Bit_Input one bit inside a word · …_I32/U32/F for 32-bit values. If the doc says the word order is reversed (LSW first — energy meters often do), use the _W variants.
  • addr — the register number exactly as the device documentation prints it (strip a 4xxxx/3xxxxx prefix: 40101 → 101). The subtract_one option handles the 1-based offset globally — never subtract yourself. Address and datatype together give driver_id = 0_<readfunc>_<addr>.
  • bit — 0–31 for one bit inside the word, or nibble syntax 5#4; the bit is appended to the driver id (0_3_100.4). Use a Bit_* datatype, and the motherword row is created for you on generate. Alarm bits: alarm letter A + group alm.

Alias — system no, tag, text, extra

These four join in a fixed order to make the text the operator reads: system_no-tag-text-(extra) → 360.001-RT401-Romtemperatur-(1=Drift). An empty field contributes nothing, and use_system_no/use_tag/use_extra in the Project card switch the parts off wholesale.

  • system no — the plant's system number for this point, 360.001. Usually the same for a whole block of rows.
  • tag — the short component tag, RT401.
  • text — short Norwegian description; the only alias part that is always included. Reserve. marks a spare row: it stays in the list but is written inactive even with force_active on.
  • extra — the parenthesised suffix. Overwritten on generate when statetext_in_alias is on and the row has a state list.

Presentation — unit, scale, dec

  • unit — a key in the unit table (autocomplete); it becomes eng_unit. Temperature = C. Missing unit? Leave empty and add it to the table rather than inventing a spelling.
  • scale — a key in the scaling table. Doc says "value × 0.1" → x0.1. The table supplies the whole block at once: scale factor plus raw and engineering min/max.
  • dec — 0–3 display decimals, written as format = %.Nf. Blank leaves the format empty. Pair it with the scale: x0.1 → dec 1.

Behaviour — alarm, rw, freq, onl

  • alarm — priority letter written to plant_pri: A alarm (the fleet default), B/C lower priorities, N note. With auto_groups and alarms_to_alm both on, a lettered row is moved into the alm group.
  • rw — rw only when the documentation says the register is writable (setpoints, commands); everything else r. Bit rows are promoted to vr/vrw automatically. Writable rows also get the write half of the driver id.
  • freq — polling override; blank means derived, which is almost always right: analog and integral values poll norm read-only / slow writable, digital IO polls slow. Override with fast, norm, slow, once or never — use slow for rarely-changing measured values such as energy totals. Logging follows from it: norm/fast log min/1; on slow, read-only analog and integral values still log min/1 (house rule 2026-08-18) while setpoints and digitals log on change; once/never log on change.
  • onl — tick on 1–3 reliable, always-readable points (a temperature or status register). IWMAC uses them to detect that the unit is online, and validation fails when no point is marked.

Display extras — state, no grp

  • state — id of a list from the State texts card; it is serialized to IWMAC JSON in format_extra, so the operator sees Drift rather than 1. Suppressed for read-only rows when statetext_only_rw is on.
  • no grp — keep this row out of the groups block, so it exists as a parameter but does not appear in the operator's menu. Synthesized motherwords are excluded on their own while exclude_motherwords_from_groups is on.

Working with rows

  • ⧉ duplicates a row with addr + 1 — the fastest way through a sequential register block. Every driver_id and element_id must be unique; duplicates are caught by Validate.
  • A project file can carry fields this table does not show — element_id, menu, active, range_min/range_max. They are preserved on load and written back out untouched; editing a row here does not drop them.

Units & driver (iw_sys)

help
Registers the physical devices and the driver in IWMAC — the iw_sys_* blocks at the end of the SQL. Skip this card entirely when the plant already has the driver and units configured (both checkboxes off = nothing emitted).
  • units block — one iw_sys_plant_units row per device below, plus the order-number link. settings block — the iw_mb.exe process registration and all driver communication settings.
  • owner/driver name ties everything together (e.g. EM270, GRUNDFOS) — it is the settings owner, the driver_type and the process name.
  • Devices: one row per physical unit on the bus — ID01 / Carel EVD 01 / addr 1, ID02 / Carel EVD 02 / addr 2 … The address prefix (0_/1_) is added automatically; ⧉ duplicates a device with the next number and address.
  • comm — TCP: fill IP (port 502 default). RTU: COM port, baud, parity, stop bits. Values land in iw_sys_plant_settings; everything else uses the standard driver defaults.

Workflow & tips

Typical workflow: ① fill table name + plant and check subtract_one against the device docs → ② add groups (start with the defaults) → ③ define state lists for enumerated registers → ④ enter points, or Import project a Copilot-generated JSON → ⑤ register the devices and driver under Units & driver, or leave both blocks off when the plant already has them → ⑥ Validate, fix what it lists → ⑦ Generate. The cards are in that order down the page.
  • Let Copilot do the typing: give it the device's register PDF together with the authoring guide (docs/11-ai-json-authoring.md in the repository); it returns a JSON file that Import project loads directly.
  • Continue later: the editor autosaves in this browser — reopening the page restores unsaved work. Export downloads the project as a file (.yaml or .json by the name you type) for keeping, mailing or another machine; Import project brings it back.
  • Old Excel workbooks: convert with modbusgen import-xlsm old.xlsm (CLI), then open the result here.
  • Direct link to a project: add #file-name to the page URL, e.g. …/#example-em24-gavazzi.json.
  • copy SQL under the preview copies the whole script to the clipboard; the chip shows how many INSERT statements it holds.
  • Missing datatype, unit or scale key? Do not improvise — extend data/tables/*.csv in the repository so every future list can use it too.
